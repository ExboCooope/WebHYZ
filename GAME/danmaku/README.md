# 避弹算法（弹幕感知 / 弹型分解 / 自主躲避 / 操作评价）

> 灵感与术语来自《STG弹幕分类与泛用技巧》（ESC，2021，B 站 cv9086374）：
> 固定弹、随机弹、自机狙、封位弹、稳定弹、多重弹、复数弹、甩弹、单源弹、交叉弹/对称弹，
> 以及微移、折返、∞折返、立回、混线、亲变更、即死、超即死、反进法。
> 本目录把其中**能算的部分**做成了可运行、可测试、可视化的代码。

## 分层

| 文件 | 层 | 干什么 |
|---|---|---|
| `danmaku_core.js` | 感知 | 视野过滤（半径/扇形/反应延迟）+ 跨帧记忆（id 关联、丢失外推、遗忘）+ 自机位置历史 |
| `danmaku_pattern.js` | 分解 | 按回推的发弹源聚类，分出多重/复数/甩/圈/圈甩/狙/静止，带置信度 |
| `danmaku_ai.js` | 决策 | 预测 → 候选动作滚动推演 → 打分选动作；技巧命名；影子自机；接管；评价 |
| `danmaku_overlay.js` | 可视化 | 每关自动挂载，驱动 `danmakuAI.step()`，并画弹型连线/影子自机/评价面板 |

全部是 ES5 普通函数 + 全局对象，**不依赖引擎**（只有 `danmaku_ai.js` 顶部的引擎适配函数和
`danmaku_overlay.js` 碰全局），所以前三个文件可以在 Node 里直接单测。

## 开关

```js
stg_show_danmaku_ai = 0;   // 关
stg_show_danmaku_ai = 1;   // 分析 + 画弹型/影子自机/评价面板
```
定义在 [STGGLOBAL.js](../../STGGLOBAL.js)。运行期在控制台改即可，下一帧生效。

> 当前仓库里默认是 **`stg_show_hitbox=1` + `stg_show_danmaku_ai=1`**（都开着，方便直接看效果）。
> 平时玩建议改回 0。
> 单帧开销（157 发弹幕、144 发在视野内实测）：`step()` 约 1.3ms（分型 0.65 + 规划 0.69）、
> 绘制约 0.1ms —— 也就是 60fps 预算（16.7ms）的一成左右。

## 1. 感知与记忆（danmaku_core）

```js
danmakuCore.update(raw, player, viewCfg)   // raw 是普通数组，便于单测
danmakuCore.tracks                          // 记忆：{id,x,y,vx,vy,r,age,lost,seen,src}
danmakuCore.visible()                       // 视野内（lost<=1）
danmakuCore.minClearance(x,y,r)             // 到最近弹幕的"间距"，负数=重叠
```

- **视野**：`view.radius`（默认 300px）、`view.cone`（扇形张角，0=整圆）、
  `view.reaction`（新弹出现多少帧后才被"看见"，模拟反应延迟）、`view.max_bullets`。
- **记忆**：每帧先按速度外推，再用空间哈希找最近邻关联（门限 `gate`）。
  丢失的弹不立刻消失，`lost` 累加，超过 `lost_max`（14 帧）才遗忘 ——
  这就是"看见的弹幕 + 记忆中的弹幕"的合并结果。
- `src` 指回引擎对象，分类时可用 `src.frame` 拿到**精确弹龄**（回推发弹源的关键）。

## 2. 弹型分解（danmaku_pattern）

先把每发弹沿自己的速度方向回推 `age` 帧，得到**发弹源估计点** `origin = pos - v*age`，
再按 **源点 + 速度** 聚类（源点容差 22px，速度用相对容差 `max(0.06, sp*4%)`），
然后**按发射帧把簇切成若干「波」**（同一帧发射的一批算一波），最后看"波与波"的关系分型：

| 判据 | 结论 |
|---|---|
| 只有一波，角度跨度 < 0.05 rad | **多重弹**（同向一列；再按沿方向的投影排序，判速度递增/递减） |
| 只有一波，角度跨度 ≥ 5.5 rad | **圈弹** |
| 只有一波，中间 | **复数弹** |
| 多波，相邻两波的旋转量**同号且一致率 ≥ 60%**（至少 3 波） | **甩弹**（`sweep` 给方向） |
| 甩弹 + 每波本身铺得开（≥ 90°）或整组跨度够 360° | **圈甩** |
| 多波、不转、但每波都宽 | **圈弹**（连续发圈） |
| 多波、同角度 | **多重弹** |
| 速度相对离散 < 8% | 稳定弹（`stable`） |
| 射线经过自机某个历史位置（角度容差 `0.09 + atan((r+pr+2)/d)`） | **自机狙**（`aimed`，并给出瞄准误差和对应帧） |
| 速度 ≈ 0 | **静止弹**（激光停摆、墙） |
| 两组源点接近、扫射方向相反 | **交叉弹**（互相 `cross` 记 id） |

### 三个踩过的坑（都是真机数据逼出来的）

1. **不能用"数组顺序里相邻两发的角度差"判甩弹**。真机上同一帧发射的 12 发，`_hit_pool`
   里的顺序恰好是创建顺序（角度递增），而记忆里关联出来的顺序是乱的 —— 于是同一画面
   真值判 `ring_whip`、记忆判 `fan`。改成按"波"比较角度集合后与顺序无关。
2. **一波里的角度不是"弹数"等分的**。这一作的圈弹用
   `stgCreateShotW2(..., angle_spread=360)` 铺满一圈，`angle_add = 360/(n-1)`，
   于是 12 发只有 11 个互不相同的角度（首尾重合）。对称阶数要用**谐波集中度**
   `C(m)=|Σ e^{i·m·θ}|/n` 去试，取 C 最大的那个 m（本作 lDY 是 11 阶、mZY 是 7 阶）。
3. **同一个 Boss 会从同一点同时发好几种弹**（lDY 2.5 / mZY 2.0 / sXY 1.8，速度只差 0.2~0.5）。
   只按源点聚类会把它们混成一锅，角度网格直接废掉；必须把**速度**也当作聚类维度，
   而且要用相对容差（绝对容差 0.45 分不开 2.0 和 1.8）。

> 波与波的旋转量：对 n 重对称的一圈弹用 **n 次谐波取相位**
> `φ = arg(Σ e^{i·n·θ}) / n`，圈整体转多少相位就转多少，而且**跟看见几发无关**
> （缺掉几发不影响各发同相），特别适合视野被裁掉一半的情况。
> 相位天然只有模 2π/n 的意义 —— 12 发里"转 23°"和"转 -7°"是同一件事，取那个慢的。

输出：

```js
{ groups:[{id,kind,label,origin:[x,y],n,spread,speed,stable,aimed,aim_ratio,aim_err,
           sweep,sweep_mag,seq_consistency,volleys,order,conf,bullets:[track…]}],
  singles:[…], cross:[{a,b}], statics:n }
```

## 3. 决策（danmaku_ai）

### 规划器 `planMove(x,y,r,obs,bounds,opt)`

候选动作 = 8 方向 × {高速, 低速} + 原地不动（共 17 个），每个候选把自机按引擎的移动规则
（斜向 `/1.4142`）推演 `horizon`（44）帧，沿途对预测弹幕算：

```
score = minClearance*12        // 整个视界里最小间距，最重
      - dangerSum*1.1          // 间距小于 safety_margin(8px) 的累计量
      - travel*0.012           // 少动一点（即死/超即死更稳）
      + (py - y)*0.35          // 贴底偏好
      - turn*3.5               // 与上一帧决策方向不一致就扣（防抖）
      + hintBonus              // 技巧偏置
```

**技巧不是硬编码动作**，而是"分类结论 → 给候选加偏置"：

| 弹型结论 | 提示 `hint` | 偏置 |
|---|---|---|
| 只有自机狙 | `micro` | 偏好低速横向小步（微移） |
| 有甩弹、没有圈弹 | `cross` | 偏好高速横向（混线/反进） |
| 只有圈弹 | `stay` | 偏好不动（找安全区即死） |
| 只有多重弹 | `stay` | 偏好不动（即死/超即死） |

最后再从"选中动作 + 弹型 + 是否与上一帧反向"回读成名字：
`即死 / 超即死 / 微移 / 混线 / 折返 / 反进法 / 走位`。

### 影子自机与对照

- `danmakuAI.ghost`：只看**视野内**弹幕的影子自机，每帧按规划移动，碰到就记一次并回版底重生；
- `danmakuAI.idle`：同一弹幕里**站桩不动**的对照组（同样大小的判定）。
两个影子吃的是同一串子弹，所以 `AI 命中 / 站桩命中` 是公平对比。

### 接管真实自机（自主躲避）

```js
danmakuAI.takeOver(stg_players[0]);   // 接管
danmakuAI.release(stg_players[0]);    // 交还
```
实现用的是引擎自己的 AI 钩子：`player.on_ai`（空函数，跳过键盘移动）+
`player.on_ai_after_move`（把上一帧算好的方向写成 `key[]`，引擎随后按 `move_speed` 移动）。
一帧的决策延迟是真实的（人也有反应时间）。

## 4. 评价真实玩家（`danmakuAI.report`）

| 字段 | 含义 |
|---|---|
| `clear` | 当前到最近弹幕的间距（像素，负数=已在判定内） |
| `min_clear` | 本关最小间距 |
| `danger` / `danger_ratio` | 间距小于安全阈值的帧数 / 占比 |
| `ttl` | 如果自机**原地不动**，还有几帧会被撞（999=视界内安全） |
| `motion` | 最近 30 帧轨迹判定出的动作：即死/不动、微移、折返、横拉、上下拉、绕圈 |
| `technique` | 规划器认为**当前该用**的技巧 |
| `regret` | "后悔值"：规划器这一帧能拿到的间距 − 实际拿到的间距，累加 |
| `player_hits` | 真实自机中弹次数（状态跳进 `PLAYER_HIT` 算一次） |
| `score` | 0~100：`100 - 危险帧占比*55 - 中弹*8 - 负间距惩罚 - 贴脸惩罚` |

`motion` 与 `technique` 对照，就是"他实际用的技巧 vs 这段弹幕该用的技巧"；
`regret` 越大说明越多次"本可以躲得更好"。

## 5. 可视化

`layer 99` 的 UI 画布自绘（和命中判定 overlay 同一套机制）：

- 每发弹一个点，颜色 = 所在弹型的颜色（多重=橙、复数=青、圈=黄、甩=品红、圈甩=红、静止=灰、未归类=白）；
- 大判定（半径>10）只画轮廓，避免糊屏；
- **每组只用一根线把成员连起来**：多重弹按沿射线的距离排序（连出来是直线），
  依次发射的按弹龄排序（甩弹连出来是螺旋），同时齐射的按角度排序（复数弹/圈弹连出来是圆弧）；
  相邻两发隔超过 56px 就抬笔，免得一整圈弹幕被连成横跨全屏的乱线；线色 = 该弹型的颜色。
  场上不再写"弹型×数量"的文字；
- 影子自机：绿色十字 + 轨迹 + 当前方向；
- 左上角面板：弹型统计 / 技巧提示 / 当前规划 / 实机评价 / 看见与记忆数量。

> 注意 UI 画布平时在场地画布之上（ui=20 > frame=5），但读盘时 frame 会被临时抬到 30，
> 那样 UI 画布被压住就什么都看不见。`danmakuView.ensureOnTop()` 会保证 UI 画布在上。

## 7. 已知局限

1. **匀速直线假设**：记忆里只存速度，带加速度/转向的弹幕会被线性外推（分类也受影响）。
2. **发弹源移动会拆组**：源点回推假设源不动；Boss 边走边发的甩弹会被拆成多簇（文章里提到过这个现象）。
3. **激光预警没接**：`BasicAI.ai_warning`（`StraightLaser` 蓄力时登记的判定）还没有并入预测，
   所以正在展开的激光只能看到"当下长度"。
4. **一帧决策延迟**：接管时用的是上一帧的规划（`on_ai_after_move` 阶段不能重算，否则同帧会跑两遍分析）。
5. **代价**：17 个候选 × 44 帧 × 视野内弹数（约 100~500），每帧几万次距离计算；
   压力测试（9000 发）时建议关掉或调小 `horizon` / `view.max_bullets`。
6. **弹型是启发式**：阈值（角度容差、源点容差、一致率）都是拍的，界面上给的是"结论+置信度"，不是真值。
